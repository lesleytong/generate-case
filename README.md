# Generate Case — 测试用例生成 Skill

基于 Agent Skills 框架的测试用例自动生成工具。通过读取代码仓库、需求文档、技术文档和 UI 设计图，自动分析代码变更、评估回归范围，并生成冒烟用例、全量用例及配套校验清单。

## 功能介绍

- 分析功能分支相对主干的代码变更，识别高风险改动（公共方法、接口、数据库）
- 评估必测范围、关联回归范围和可选回归范围
- 根据需求文档、技术文档、UI 图生成全量测试用例（Markdown 思维导图格式）
- 生成覆盖核心主流程的冒烟用例（步骤与界面预期合并写，并附接口校验和数据表校验）
- 同步生成日志校验清单、SQL 校验清单和 Bug 预测清单

## 目录结构

```text
generate-case/
├── SKILL.md                          # Skill 定义文件（AI 执行入口）
├── README.md                         # 本文件
├── references/                       # 所有参考资料放这里
│   ├── repo/                         # 目标代码仓库（完整 clone，已切换到功能分支）
│   ├── requirements/                 # 需求文档（PRD、用户故事、变更说明等）
│   │   └── *.md / *.txt / *.pdf
│   ├── technical/                    # 技术文档（接口文档、数据库设计、系统架构等）
│   │   └── *.md / *.txt / *.yaml / *.json
│   └── ui/                           # UI 设计图（界面截图、设计稿等）
│       └── *.png / *.jpg / *.webp
└── output/                           # 生成结果输出目录（由 AI 自动创建）
    ├── 代码分析.md                    # 分支变更分析 + 回归测试范围建议
    ├── 冒烟用例.md                    # 核心主流程冒烟用例（含接口校验 + 数据表校验）
    ├── 全量用例.md                    # 完整测试用例（思维导图格式，三层预期结果）
    ├── 需要检查的日志.md               # 各用例对应的日志关键词与验证命令
    ├── 需要检查的SQL.md               # 各用例对应的数据表校验 SQL
    └── 可能发现的Bug.md               # 结合代码分析推断的高风险 Bug 与对应用例
```

## 三种工作模式

| 模式 | 触发关键词 | 输出文件 |
|------|-----------|----------|
| 代码分支分析 | "分析分支"、"回归范围"、"代码变更" | `output/代码分析.md` |
| 全量用例设计 | "生成用例"、"测试用例"、"全量用例" | `output/全量用例.md` + `output/需要检查的日志.md` + `output/需要检查的SQL.md` + `output/可能发现的Bug.md` |
| 冒烟用例生成 | "冒烟用例"、"smoke test"、"主流程验证" | `output/冒烟用例.md` |

三种模式可单独使用，也可以组合使用（如："分析分支变更，并生成冒烟用例和全量用例"）。

## 使用步骤

### 第一步：准备代码仓库

将目标仓库 clone 到 `references/repo/`，并切换到功能分支：

```bash
cd references
git clone <仓库地址> repo
cd repo
git checkout <功能分支名>

# 确认当前分支
git branch
```

若系统包含多个服务仓库（如后端服务、前端工程），可分别 clone 到 `references/repo/` 下的子目录，例如 `references/repo/backend/`、`references/repo/frontend/`。

### 第二步：放入其他参考资料

- `references/requirements/` — 放入需求文档（PRD、用户故事、变更说明等）
- `references/technical/` — 放入接口文档、数据库 ER 图说明、系统架构文档等
- `references/ui/` — 放入页面截图或设计图

参考资料不必全部准备齐全，AI 会根据现有资料生成内容，缺失部分标注【待补充】。

### 第三步：触发生成

在 Cursor 中输入，例如：

```text
根据功能分支 feature_xxx 的代码变更、需求文档、技术文档、UI 图，
生成代码分析结果、冒烟用例和全量用例。
```

AI 将自动读取所有参考资料，生成结果并保存到 `output/` 目录。

## 输出说明

| 输出文件 | 内容说明 |
|----------|----------|
| `output/代码分析.md` | 变更文件列表、核心变更说明、公共方法变更（高风险）、API 及数据库变更、回归测试范围建议 |
| `output/冒烟用例.md` | 覆盖核心主流程，用例数量精简（10～30 条）；每条用例包含步骤与界面预期（用户视角）、接口校验（HTTP 状态码 + 响应体关键字段）、数据表校验（字段预期值） |
| `output/全量用例.md` | 覆盖正向流程、边界值、异常场景、权限验证等，Markdown 思维导图格式；每条用例预期结果分三层：界面反馈、接口校验、数据表校验 |
| `output/需要检查的日志.md` | 按用例模块分组，列出日志关键词、级别、触发时机、预期内容和 grep 查询命令；重点标注 WARN/ERROR 级异常日志 |
| `output/需要检查的SQL.md` | 按用例模块分组，包含前置数据准备、结果验证、数据清理三类 SQL；附数据一致性通用检查语句 |
| `output/可能发现的Bug.md` | 从代码逻辑漏洞、公共方法副作用、并发事务、字段一致性、异常处理五个维度预判高风险 Bug，每条 Bug 关联具体用例编号 |

## 注意事项

- 代码仓库须在使用前完成 clone 并切换到目标功能分支，AI 不会自动执行 git clone
- 全量用例输出为 Markdown 思维导图格式（标题层级 + 无序列表），不使用表格格式
- 冒烟用例每条必须包含接口校验和数据表校验，纯查询类用例数据表校验标注"无写操作，不涉及数据表变更"
- 日志校验清单、SQL 校验清单、Bug 预测清单与全量用例同步生成，不可省略
- 针对海外信贷系统，AI 会主动关注金额精度、利率换算、还款计划、多币种、KYC 等金融场景特有测试点
